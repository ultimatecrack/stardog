# Stardog with Python: Tutorial

A hands-on tutorial from knowledge graph basics to GraphRAG and agents, using **pystardog** against **Stardog Cloud**. Full plan: [CURRICULUM.md](CURRICULUM.md).

## Getting started

1. Create a `.env` file in the **project root** (one level up), based on [00_setup/.env.example](00_setup/.env.example).
   Check it with `.venv\Scripts\python stardog_tutorial\00_setup\check_setup.py` (run from the project root). All five checks should pass.
2. Open a notebook in `notebooks/` and select the project's `.venv` as the kernel (VS Code: *Select Kernel → Python Environments → .venv*).
3. Run the cells in order.

Each chapter writes only to its own named graphs (`urn:tutorial:chNN:*`) and removes them at the end, so chapters never interfere with each other or with other data in your database.

## Folders

| Folder | Contents |
|---|---|
| `00_setup/` | `.env.example`, `check_setup.py` |
| `data/` | Datasets, one folder each: `company/` (Ch 1-2), `recipes/` (Ch 3-9: source CSVs in `csv/`, `recipes.ttl` generated by Ch 3, `ratings.nt.gz` generated by Ch 5, `llm_cache.json` cached LLM answers for Ch 16), `edugraph/` (Ch 10+: `curriculum.ttl`, SIS exports in `sis/`, lesson texts + cached LLM extractions in `lessons/`, `agent_llm_cache.json` cached agent conversations for Ch 17), `supply_chain/` (Ch 12, 15b: `network.ttl` with coordinates), `generators/` (scripts that generate data, incl. the Ch 15 scale EduGraph) |
| `ontology/` | Ontologies in Turtle: `recipes.ttl` (Ch 7+), Stardog rules `recipes_rules.ttl` (Ch 8+), SHACL shapes `recipes_shapes.ttl` (Ch 9+) and `edugraph_shapes.ttl` (learning-plan guardrails, Ch 17), SMS2 mappings in `mappings/` (Ch 10+) |
| `notebooks/` | One notebook per chapter |
| `api/` | EduGraph REST API (FastAPI, Ch 13+): `main.py` (API key + least-privilege Stardog user from Ch 14) |
| `agents/` | `mcp_server.py`: the EduGraph tutor tools as an MCP server (Ch 17) |
| `ops/` | `deploy_edugraph.py`: repeatable deploy / teardown with smoke test (Ch 14) |
| `tests/` | pytest suite, each test in temporary named graphs: `..\.venv\Scripts\python -m pytest tests -q` |
| `src/kg/` | Reusable Python code: `client.py` (connections, transactions, error advice, setup check), `sparql.py` (`run_query()` and friends), `recipes.py` (IRI conventions, recipe → RDF), `updates.py` (idempotent upsert), `models.py` (register named models for reasoning / Explorer), `reasoning.py` (explanations, consistency, query plans), `validation.py` (SHACL reports, validation gate), `imports.py` (CSV/JSON imports through mappings), `extraction.py` (Ollama concept extraction + entity linking), `dboptions.py` (change database options, offline if needed), `stored_queries.py` (publish `.rq` files as stored queries), `security.py` (roles, users, permissions), `backup.py` (logical backup / restore), `perf.py` (benchmarks, plans, profiles), `analytics.py` (graph algorithms via the Stardog Spark connector in `../tools/`), `llm.py` (text-to-SPARQL, GraphRAG, tool calling with Ollama), `agent.py` (minimal agent loop with a trace), `tutor.py` (EduGraph tutor tools: read tools, SHACL-guarded `save_plan`, graph memory, PROV-O provenance) |
| `src/kg/queries/` | SPARQL queries as `.rq` files, one folder per dataset (`recipes/`, `edugraph/`) |
